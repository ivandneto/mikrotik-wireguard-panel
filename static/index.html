🔒 Segurança

⚠️ NUNCA exponha o painel na internet. Ele tem acesso de configuração aos seus MikroTiks. Acesse só pela rede local ou pela VPN WireGuard — para usar de fora de casa, conecte primeiro na VPN e então abra o painel.

1. Não crie liberação de porta para o painel

O painel só fica exposto se existir um port forward apontando para ele. Nunca libere a porta do painel (8080) na tela "Liberação de portas" nem no Winbox. Confira no terminal do MikroTik — as duas listas devem vir vazias:

/ip firewall nat print where dst-port=8080
/ip firewall nat print where to-ports=8080

2. Painel em Docker (PC/servidor)

  • No docker-compose.yml, publique a porta só no IP da LAN: "192.168.88.61:8080:8080" (troque pelo IP da máquina) e rode docker compose up -d.
  • Windows (PowerShell como Administrador) — libera a porta só para a rede local e a VPN:
    New-NetFirewallRule -DisplayName "WG Panel (só LAN e VPN)" -Direction Inbound -Protocol TCP -LocalPort 8080 -RemoteAddress LocalSubnet,10.10.0.0/24 -Action Allow
  • Linux: o Docker ignora o ufw nas portas publicadas — o item anterior (publicar só no IP da LAN) é o que protege. Veja o SECURITY.md para a chain DOCKER-USER.

3. Painel em container no MikroTik

Cole no terminal do MikroTik (ajuste as faixas da sua rede e da VPN). Só a rede local e a VPN chegam no painel:

/ip firewall address-list add list=wgpanel-acesso address=192.168.88.0/24 comment="WG Panel: rede local"
/ip firewall address-list add list=wgpanel-acesso address=10.10.0.0/24 comment="WG Panel: VPN"
/ip firewall filter add chain=forward action=drop protocol=tcp dst-address=172.20.0.2 dst-port=8080 src-address-list=!wgpanel-acesso comment="WG Panel: painel so para LAN e VPN" place-before=[:pick [/ip firewall filter find where dynamic=no] 0]

4. Teste

  1. No celular, desligue o Wi-Fi e a VPN (só 4G) e abra http://SEU-DDNS:8080 — não pode abrir.
  2. Ligue a VPN e abra pelo IP interno do painel — deve abrir.

Se o item 1 abrir o painel, ele está exposto: revise a liberação de portas imediatamente.

Outras boas práticas

  • Senha forte no admin do painel e usuários "Somente leitura" para quem só acompanha.
  • No MikroTik, o painel usa o usuário wgpanel limitado — nunca o admin. Restrinja a API (IP → Services) às redes de onde o painel acessa.
  • Guarde com cuidado o .env, a pasta data/ e os backups: contêm senhas e as chaves da VPN.

📊 Painel

Visão geral do que está acontecendo agora no roteador escolhido no seletor do topo. Atualiza sozinho a cada 15 segundos (o botão ⟳ força uma coleta imediata).

  • Seus roteadores — aparece quando o painel gerencia mais de um MikroTik: 🟢/🔴 de cada um, modelo, CPU e tempo ligado. Clique num deles para trocar.
  • Roteador — modelo, versão do RouterOS e há quanto tempo está ligado.
  • CPU / Memória — uso atual. CPU alta por muito tempo pode deixar a internet lenta.
  • VPN WireGuard — quantos clientes (dispositivos e MikroTiks remotos) deste roteador estão conectados agora, somando todas as interfaces dele.
  • Portas liberadas — quantas liberações estão ativas e se os servidores estão respondendo.
  • Tráfego da internet — download/upload do seu link. A interface de internet é detectada sozinha pela rota padrão (ex.: pppoe-out1); o nome aparece embaixo do gráfico.
  • Eventos recentes — últimos acontecimentos: alguém conectou, servidor caiu, porta expirou…

🖧 Roteadores (vários MikroTiks)

O painel gerencia o seu MikroTik (o "principal", do arquivo .env) e também os MikroTiks dos seus clientes. O seletor no topo escolhe qual você está vendo: VPN, portas, gráficos e configurações passam a ser daquele roteador.

Como adicionar o MikroTik de um cliente (recomendado)

  1. Em VPN → 🖧 Outro MikroTik, crie o túnel com a opção "Gerenciar este MikroTik pelo painel" ligada (padrão).
  2. Cole o script no terminal do MikroTik do cliente. Além do túnel, ele cria o usuário wgpanel com permissões limitadas, senha aleatória e login só pelo túnel, e libera a API.
  3. Em instantes o roteador aparece em Roteadores e no seletor do topo.

Túneis criados antes desta opção: use 🛠️ na linha do cliente (VPN) — o painel gera só o trecho de gerenciamento.

Por que um usuário limitado (e não o admin do Winbox)?

Se o painel fosse invadido, senhas de admin dariam controle total sobre os roteadores dos clientes. O usuário wgpanel não muda senhas nem usuários e só consegue entrar pelo túnel — pela internet ele não funciona.

Terminal

Para comandos, use 🌐 WebFig → Terminal. O painel não tem um terminal próprio de propósito: isso exigiria dar a ele acesso total aos roteadores, e o usuário wgpanel é limitado justamente para que, se o painel fosse invadido, ninguém controlasse os seus MikroTiks.

Na tela Roteadores

  • 🟢 / 🔴 status, modelo, versão, CPU, memória e quantos clientes VPN e portas cada um tem. ⬆️ RouterOS … disponível aparece quando há atualização (veja Checagem de segurança).
  • 🔌 Testar — confere a conexão; para roteadores via túnel, procura sozinho a porta certa da API.
  • 🌐 WebFig — abre a página do próprio MikroTik numa nova aba (também no topo, ao lado do seletor). Lá você entra com o seu usuário e tem o Terminal, igual ao do Winbox. Para clientes, funciona pelo túnel. Se o navegador avisar de certificado (https autoassinado), é esperado: avance.
  • ✏️ Editar — nome, endereços da VPN e (exceto o principal) URL, usuário e senha.
  • 🗑️ — tira o roteador do painel (não mexe na configuração dele).
  • ＋ Adicionar manualmente — para roteadores que o painel já alcança sem o script.

🔐 VPN WireGuard

Uma VPN cria um "túnel" seguro até a sua rede. Com ela você acessa de qualquer lugar as coisas de casa/empresa — câmeras, NAS, servidores, impressoras, o próprio MikroTik — como se estivesse lá.

O painel trabalha com dois tipos de cliente:

📱 DispositivoUm aparelho (celular, notebook). Configura escaneando um QR Code ou importando um arquivo .conf.
🖧 Outro MikroTikO roteador de um cliente e a rede inteira atrás dele. Configura colando um script no terminal do MikroTik dele. Veja Outro MikroTik.

Interfaces (as abas no topo da tela)

Cada aba é uma interface WireGuard do MikroTik, com porta e faixa de IPs próprias. Use mais de uma para separar propósitos — por exemplo wg-casa para seus aparelhos e wg-clientes para MikroTiks de clientes. O número na aba mostra online / total.

  • Painel vazio, MikroTik com WireGuard (painel novo ou reinstalado) — a tela mostra "Este MikroTik já tem WireGuard" com o botão Adotar e importar clientes: traz a interface e abre a importação; com as chaves guardadas no MikroTik, os clientes vêm com QR Code. Há também o atalho para restaurar um backup.
  • ＋ Nova interface — cria uma interface (o painel sugere porta e faixa livres) ou adota uma que já existe no MikroTik.
  • Faixa da VPN — precisa ser diferente da sua rede (sua rede é 192.168.88.x → use 10.10.0.x).
  • Redes daqui — as redes da sua casa/empresa que os clientes podem alcançar.
  • Tratar como rede interna (LAN) — deixa os dispositivos acessarem a rede, o DNS e a internet. Para uma interface só de MikroTiks de clientes, pode desmarcar.
  • ⚙️ reconfigura · 🗑️ exclui (só quando não tem clientes; pode remover também do MikroTik).

Dispositivos: o que passa pela VPN?

  • 🏠 Só rede local — acessa sua rede; a internet do aparelho continua normal. Recomendado na maioria dos casos.
  • 🌐 Toda a internet — toda a navegação passa pelo seu MikroTik. Útil em Wi-Fi público.

Ao trocar o modo de um dispositivo, o QR novo abre sozinho: escaneie de novo no aparelho (o modo fica gravado nele).

Acesso remoto × local: no QR/arquivo, use 🌍 remoto (IP público/DDNS) quando o aparelho estiver fora de casa e 🏠 local (IP do MikroTik na rede) dentro dela.

🖧 Outro MikroTik (site-to-site)

Liga o MikroTik de um cliente ao seu por um túnel. Da sua casa você abre o Winbox do roteador dele e acessa os equipamentos da rede dele (câmeras, computadores), e o painel avisa no Discord se o cliente cair.

   SUA CASA                                 CLIENTE (ex.: Padaria)
┌─────────────────┐                      ┌──────────────────────┐
│ Seu MikroTik    │◄════════ túnel ═════►│ MikroTik do cliente  │
│ 192.168.88.x    │   (pela internet)    │ 192.168.10.x         │
│  └ seu PC       │                      │  ├ câmeras           │
│  └ painel       │                      │  └ computadores      │
└─────────────────┘                      └──────────────────────┘

Passo a passo

  1. Uma vez só: crie uma interface para clientes (＋ Nova interface, ex.: wg-clientes).
  2. Na aba dela, clique em 🖧 Outro MikroTik e informe o nome e a rede local do cliente (veja no Winbox dele em IP → Addresses, ex.: 192.168.10.0/24).
  3. Escolha quem acessa quem (abaixo) e deixe ligado "Gerenciar este MikroTik pelo painel" se quiser criar VPN, portas e ver gráficos do roteador dele aqui (informe a porta do WebFig dele — padrão 80).
  4. O painel mostra um script. No Winbox do MikroTik do cliente → New Terminal → cole e aperte Enter (uma única vez). Dá para copiar ou baixar o .rsc.
  5. Em segundos ele aparece Online. Acesse o roteador dele pelo IP no túnel (coluna "IP VPN", ex.: 10.20.0.2) e os aparelhos pelo IP normal da rede dele (ex.: 192.168.10.50).
  6. Se marcou "Gerenciar", ele também aparece em Roteadores e no seletor do topo.

Quem acessa quem?

➡️ Só eu acessoVocê entra na rede do cliente; o cliente não abre conexões para a sua rede. Recomendado e padrão. O painel cria no seu MikroTik uma regra que bloqueia só conexões novas vindas do cliente.
↔️ Mão duplaOs dois lados se acessam. Use só se o cliente realmente precisar de algo da sua rede.

Pode trocar depois pelo ✏️, sem mexer no MikroTik do cliente.

O que o painel faz em cada lado

  • No seu MikroTik: o peer do cliente, as rotas para a rede dele e (no modo "só eu acesso") a regra de bloqueio.
  • No MikroTik do cliente (pelo script): a interface wg-central apontando para o seu DDNS, o IP no túnel, as rotas para a sua rede e a inclusão do túnel na lista LAN dele (para você conseguir entrar no Winbox).
  • Com "Gerenciar" ligado, também: o usuário wgpanel (grupo limitado, senha aleatória, login só pelas redes do túnel) e o serviço www liberado para a API. Se o www dele já estiver em uso com restrições, o script avisa o que ajustar.

⚠️ As duas redes precisam ser diferentes. Se o cliente também usa 192.168.88.x (padrão de fábrica do MikroTik, igual à sua), o painel recusa — mude a faixa da rede do cliente antes. O script contém a chave do túnel: envie por um canal seguro.

Para refazer no cliente (ex.: após 🔑 gerar chaves novas): no MikroTik dele, remova a interface wg-central e rode o script novo.

🎮 Liberação de portas

Também chamado de port forward ou redirecionamento de porta. Permite que pessoas na internet acessem um serviço da sua rede — por exemplo, amigos entrando no seu servidor de Minecraft.

Antes de liberar

  • Fixe o IP do servidor: no Winbox, IP → DHCP Server → Leases → clique no servidor → Make Static. Se o IP mudar, a liberação para de funcionar.
  • Libere também o firewall do próprio servidor (ex.: Firewall do Windows).

Campos

  • Modelo pronto — preenche as portas certas de jogos e apps conhecidos.
  • Porta externa — a porta que as pessoas usam na internet. Aceita 25565, faixa 2456-2458 ou lista 80,443.
  • IP do servidor / Porta interna — para onde o tráfego vai. Porta interna em branco = mesma da externa.
  • Permitir apenas destes IPs — só esses endereços conseguem acessar. Ótimo para jogar só com amigos ou para RDP/SSH.
  • Fechar automaticamente — a porta fecha sozinha no horário escolhido (ex.: liberar só no fim de semana).
  • Monitorar se está no ar — o painel testa a porta do servidor e avisa se ele cair (apenas TCP).

🛠️ Ferramentas admin

Testes feitos pelo próprio MikroTik escolhido no seletor do topo — é como rodar o comando no terminal dele, sem abrir o Winbox.

  • 📶 Ping — confere se o roteador alcança um endereço e quanto tempo a resposta leva. Bom para testar um cliente da VPN (ex.: 10.10.0.2), um servidor da rede (ex.: o do Minecraft) ou a internet (8.8.8.8).
  • 🧭 Traceroute — mostra o caminho até o destino, salto a salto. Ajuda a ver onde a conexão para ou fica lenta. Saltos com "*" não responderam (comum em roteadores de operadora).

Com vários roteadores, troque no seletor para testar a partir do MikroTik de um cliente (ex.: ele alcança a câmera da rede dele?).

📈 Gráficos e consumo

  • Gráfico — escolha um cliente VPN (dispositivo ou MikroTik remoto) ou uma porta liberada e o período (1 hora a 30 dias). Para VPN: Download = o que o dispositivo recebeu; Upload = o que enviou. "Online X% do tempo" mostra quanto ficou conectado. Para portas: tráfego que entrou e a disponibilidade do servidor.
  • Consumo por cliente — quanto cada dispositivo usou no período e quando foi visto por último.

O histórico é guardado pelo tempo definido em Configurações (padrão 30 dias).

🔔 Eventos

Linha do tempo automática do sistema: conexões e desconexões da VPN ("VPN: …" para dispositivos, "Site: …" para MikroTiks de clientes), servidores que caíram/voltaram, portas que expiraram, regras apagadas por fora e quedas do MikroTik. Com vários roteadores, cada evento começa com o nome dele (ex.: [Padaria] MikroTik inacessível). Tudo é registrado aqui, mesmo o que não gera alerta.

Cores: success algo bom · info informativo · warn atenção · error problema.

📣 Alertas admin

Envia os eventos para o seu celular via Discord e/ou Telegram.

  • Discord — no canal desejado: Editar canal → Integrações → Webhooks → Novo webhook → Copiar URL. Cole no painel e ative.
  • Telegram — crie um bot com o @BotFather (/newbot), mande uma mensagem para o bot e pegue o Chat ID em api.telegram.org/bot<TOKEN>/getUpdates.
  • Quando avisar — escolha quais eventos geram mensagem. Valem para todos os roteadores; cada aviso diz de qual roteador é. A queda de um roteador de cliente só é avisada depois que ele já esteve online (não alerta enquanto o script ainda não foi colado).
  • Avisos do roteador — "Atualização do RouterOS disponível" (verificada uma vez por dia) e, se quiser, "Configuração do MikroTik mudou" (quando o backup automático guarda uma cópia nova).
  • Idioma — os avisos e eventos saem no idioma escolhido em Configurações → 🌐 Idioma.
  • Use Salvar e enviar teste para confirmar que chegou.

🛡️ Checagem de segurança admin

Confere no roteador escolhido os pontos que mais expõem um MikroTik e o painel. Só lê: nada é alterado. Cada item mostra ✅ ok, ⚠️ atenção ou ❌ problema, e o comando para corrigir.

  • Acesso ao painel — avisa se você abriu o painel por um IP público (ele deve ficar só na rede local e na VPN).
  • Port forward para o painel — procura regras de NAT que levem a porta do painel para a internet.
  • Firewall de entrada — confere se existe a regra que bloqueia acessos da internet ao roteador (chain input). Sem ela, Winbox, WebFig, API e DNS podem ficar abertos.
  • Serviços — Telnet/FTP ligados (enviam senha sem criptografia) e serviços que aceitam qualquer endereço.
  • Usuários — o usuário padrão admin ativo e o usuário wgpanel sem restrição de endereço.
  • DNS aberto — DNS do roteador respondendo para a internet.
  • Atualização do RouterOS — o painel pergunta ao roteador uma vez por dia se há versão nova (e avisa no Discord/Telegram). ⬆️ Verificar atualização consulta na hora. Para atualizar: faça um backup e, no terminal, /system package update install (o roteador reinicia).

A checagem cobre os erros mais comuns, não substitui uma auditoria completa. O aviso de versão nova também aparece nos cartões dos roteadores.

👥 Usuários admin

  • Administrador — pode tudo: criar/remover clientes e portas, ver QR codes, mudar configurações.
  • Somente leitura — vê status, gráficos e eventos, mas não altera nada nem vê QR codes/chaves. Ideal para quem só precisa acompanhar.

Estes usuários são só do painel — não têm relação com os usuários do MikroTik.

💾 Backup admin

  • Baixar backup — arquivo com tudo do painel: roteadores cadastrados (com as senhas de API), interfaces, clientes (com chaves), MikroTiks remotos, portas, configurações, alertas e usuários. Guarde em local seguro: quem tiver o arquivo consegue entrar na sua VPN e nos roteadores.
  • Restaurar — importa um backup (ex.: ao trocar o painel de máquina). Itens existentes são atualizados, nada é apagado. O que faltar é recriado só no roteador principal; os dos outros roteadores entram no painel (eles já estão configurados nos MikroTiks deles). Aceita backups de versões antigas.
  • 🕒 Backup automático do MikroTik — todo dia (ou toda semana) o painel exporta a configuração de cada roteador (sem senhas) e guarda uma cópia só quando algo mudou, até o limite escolhido. 🔍 O que mudou compara com a cópia anterior (linhas com + entraram, com − saíram); ⬇️ .rsc baixa o arquivo. Ficam na pasta data/ do painel. Precisa da permissão ftp no usuário wgpanel (veja Problemas comuns).
  • Backup do MikroTik — salva um .backup e um .rsc da configuração inteira do roteador escolhido no seletor, dentro dele (Winbox → Files). Faça antes de mudanças grandes.

Trocar de painel (ex.: do PC para o container no MikroTik):

  • Tudo (VPN, portas, alertas, usuários, roteadores): Baixar backup no antigo → Restaurar no novo.
  • Só a VPN: no painel novo, em VPN WireGuard, clique em Adotar e importar clientes — com as chaves guardadas no roteador, eles vêm com QR Code. Alertas, usuários e portas você configura de novo.

Depois desligue o painel antigo para não receber alertas em dobro.

⚙️ Configurações admin

Itens marcados com 🖧 nome são do roteador escolhido no seletor; os outros valem para o painel todo.

  • Endereço remoto / local 🖧 — o DDNS/IP público e o IP local deste roteador; vão nos QR codes, arquivos e scripts criados nele. Mudou o DDNS? Atualize aqui e gere as configurações de novo.
  • Keepalive / MTU — avançado; os padrões funcionam na maioria dos casos. (DNS e redes acessíveis ficam em cada interface: VPN → ⚙️.)
  • Guardar a chave privada dos clientes no MikroTik — ligado por padrão. Permite que qualquer painel importe os clientes com QR Code. Quem for admin do MikroTik consegue ver as chaves, e elas vão junto nos backups do roteador.
  • Identificação do tráfego da internet (NAT) 🖧 — mantenha "Lista de interfaces WAN" se o seu MikroTik usa a configuração padrão.
  • 🌐 Idioma — o idioma desta tela (fica salvo neste navegador; também dá para trocar na tela de login e no menu lateral) e o idioma dos alertas e eventos (vale para todos).
  • Interface WAN 🖧 — vazio = detectar sozinho pela rota padrão (recomendado). Preencha só para forçar outra.
  • Considerar offline após — tempo sem handshake até um cliente aparecer offline. Mínimo seguro: 150 s (abaixo disso surgem alertas falsos).
  • Guardar histórico — por quantos dias manter os dados dos gráficos.

Conexão com o MikroTik principal (IP, usuário, senha, intervalo de coleta) fica no arquivo .env — ou nas variáveis do container, se o painel roda dentro do MikroTik. A dos outros roteadores fica em Roteadores → ✏️ Editar.

📜 Auditoria admin

Registro de quem fez o quê e quando: logins, clientes criados/removidos, portas abertas, QR codes visualizados, configurações alteradas.

📚 Glossário

WireGuard
Tecnologia de VPN moderna, rápida e segura, já embutida no MikroTik (RouterOS 7).
Peer / Cliente
Cada dispositivo (ou MikroTik remoto) autorizado a conectar na VPN.
Roteador principal
O seu MikroTik, configurado no arquivo .env. Os outros (de clientes) são cadastrados no painel.
Usuário limitado
O usuário wgpanel que o painel usa nos MikroTiks: lê e configura, mas não mexe em usuários/senhas; nos de clientes, só entra pelo túnel.
API REST
A "porta de conversa" do RouterOS 7 que o painel usa (pelo serviço www/www-ssl). O Winbox usa outro protocolo.
Interface WireGuard
Um "servidor" de VPN dentro do MikroTik, com porta e faixa de IPs próprias. Dá para ter várias.
Site-to-site
Túnel entre duas redes inteiras (dois roteadores), em vez de um aparelho só. É o "Outro MikroTik".
Rota
Indica ao roteador por onde chegar numa rede. O painel cria rotas para a rede de cada MikroTik remoto.
Handshake
"Aperto de mão" periódico entre o dispositivo e o MikroTik. Se aconteceu há pouco, o cliente está conectado.
Endpoint
Endereço (IP ou DDNS + porta) onde o cliente encontra o MikroTik.
DDNS
Um nome fixo (ex.: xxxx.sn.mynetname.net) que sempre aponta para seu IP, mesmo que ele mude.
NAT / Port forward
Regra que encaminha quem chega da internet numa porta para um aparelho da sua rede.
TCP / UDP
Tipos de comunicação. Cada jogo/app usa um (ou ambos) — os modelos prontos já sabem qual.
WAN / LAN
WAN = lado da internet. LAN = sua rede interna.
CGNAT
Quando a operadora não te dá um IP público próprio. Impede liberar portas e receber VPN — peça IP público à operadora.
Split / Full tunnel
"Só rede local" / "Toda a internet" pela VPN.
Whitelist
Lista de IPs permitidos; todos os outros são bloqueados.
Chave privada / pública
O par de chaves de cada cliente. A pública fica no MikroTik (o "cadeado"); a privada prova quem é o cliente. Pode ficar guardada também no MikroTik (ver Configurações).

🛠️ Problemas comuns

MikroTik offlineConfira IP e senha no arquivo .env, se o serviço www-ssl está ativo (IP → Services) e se o computador do painel está na rede permitida. Após editar o .env, rode docker compose up -d.
VPN conecta mas não acessa nadaEm VPN → ⚙️ da interface, deixe marcado "Tratar a VPN como rede interna" e aplique de novo.
VPN conectada, mas não abre um aparelho da redeO aparelho de destino está recusando a faixa da VPN (10.10.0.x):
• MikroTik (WebFig/Winbox): libere em IP → Services → available-from (ou address em versões antigas) incluindo 10.10.0.0/24.
• PC Windows: o Firewall do Windows só aceita a própria rede. Em PowerShell (admin): New-NetFirewallRule -DisplayName "VPN WireGuard" -Direction Inbound -RemoteAddress 10.10.0.0/24 -Action Allow
• Use o IP, não o nome (\\192.168.88.61 em vez de \\meu-pc). Apps que "procuram aparelhos na rede" automaticamente não funcionam pela VPN.
Painel novo/reinstalado sem os clientesEm VPN WireGuard aparece "Este MikroTik já tem WireGuard": clique em Adotar e importar clientes. Ou, para trazer tudo (alertas, usuários, roteadores), use Backup → Restaurar com um backup do painel antigo.
Roteador de cliente "Sem conexão" em RoteadoresO túnel (VPN) dele precisa estar Online. Confira se o trecho de gerenciamento do script foi colado e use 🔌 Testar, que procura a porta da API. Se o www dele aceitar só alguns IPs, o script avisa: inclua a faixa do túnel em IP → Services → www.
MikroTik do cliente não fica OnlineConfira no roteador do cliente se o script rodou sem erro (/interface wireguard print deve mostrar wg-central), se ele tem internet e se o seu endereço remoto (DDNS) está certo em Configurações. A porta UDP da interface precisa estar liberada no seu MikroTik (o painel faz isso ao criar a interface).
Túnel Online, mas não abre a rede do clienteConfira se a rede informada no cliente está certa (✏️) e se o aparelho de lá aceita conexões de outra rede (firewall do Windows, câmeras com restrição). Se o MikroTik do cliente não usa a lista LAN padrão, crie nele uma regra accept para a interface wg-central.
"Conflita com a sua rede" ao criar Outro MikroTikA rede do cliente é igual (ou se sobrepõe) à sua ou à de outro cliente. Mude a faixa da LAN do cliente (ex.: 192.168.10.0/24) antes de criar o túnel.
Peer removido pelo WinboxO painel mostra "Ausente no MikroTik". Use 🔁 para recriar ou 🗑️ no painel para remover de vez — removendo pelo painel, as rotas e regras dele também são limpas.
Atualizei o painel e não vi a mudançaConfira a versão no menu lateral (embaixo de "WG Panel") e recarregue a página. Se o painel roda no MikroTik, troque a imagem do container pelo arquivo wgpanel-mikrotik-arm64-vX.Y.Z.tar da versão nova (veja o README); o /container print mostra a versão no comentário.
VPN funciona em casa, mas não foraUse o QR de Acesso remoto fora de casa. Verifique se o endereço remoto (DDNS) está certo em Configurações.
Cliente aparece Offline mas está conectadoNormal se ficar parado sem uso por alguns minutos com keepalive desligado. Com o padrão (25s) não acontece.
Porta liberada não funcionaIP do servidor mudou (faça o lease estático), firewall do servidor bloqueando, programa fechado ou teste feito de dentro da própria rede (teste pelo 4G).
"Fora do ar" no serviçoO painel não conseguiu conectar no servidor interno: ele está desligado, o programa não está rodando ou a porta interna está errada.
"Precisa da permissão 'ftp'" (backup automático ou atualização)Painéis instalados antes da versão 1.3 criaram o usuário wgpanel sem acesso a arquivos. No terminal do MikroTik, como admin: /user group set [find name=wgpanel] policy=read,write,api,rest-api,test,sensitive,ftp. A permissão "ftp" só libera arquivos; não liga o serviço FTP.
Esqueci a senha do painelOutro admin pode redefinir em Usuários. Sem nenhum admin: apague a pasta data/ (perde os dados do painel — faça backup antes) e reinicie.
